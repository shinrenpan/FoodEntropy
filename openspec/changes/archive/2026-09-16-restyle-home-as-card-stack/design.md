## Context

首頁目前是一個 `List`，依序放環形圖、浪費統計、三個分桶 section，底部釘著「Add Food」。實測量測：兩張統計卡佔滿第一屏，第一筆食材要到約 70% 高度才出現且被底部按鈕壓掉一半；環形圖的內容與三個 section header 完全重複。

食材列的四個動作（點擊編輯、左滑標記已使用、右滑刪除、長按延長／處置）全部由 `List` 免費提供。這是本次改動最大的技術約束：任何「把列包進自訂容器」的做法都會離開 `List`，那四個動作就得自行以手勢重寫。

`navigation` 目前規定「There SHALL be one navigation stack for the whole app」——那是 `remove-tab-bar` 拿掉 tab bar 時寫下的。本次把分桶清單放進 sheet 之後，sheet 會擁有自己的導覽堆疊，該條敘述不再成立。

`app-intents` 的螢幕感知 requirement 明文標註對象是「each food row on the home list」。食材列離開首頁後，該敘述失去對應物。

`StatusChartView` 由首頁與 Widget 共用。它內部自帶分隔，直接放進卡片時會呈現為兩塊各自獨立的面板。

## Goals / Non-Goals

**Goals:**

- 首頁成為單純的儀表板：一眼看完五個區塊的摘要，不承載工作清單。
- 食材列的四個動作**完全不變**，且不需要自行實作任何手勢。
- 從分桶清單點食材開啟編輯表單時，表單推在清單所在的堆疊內，關閉後退回清單。
- 使用者可以單純瀏覽這疊卡而不被丟進 modal。
- 卡面永遠顯示真實資訊，沒有已記錄價格時也不留空、不補零。
- 切換分桶時整疊高度不跳動。

**Non-Goals:**

- 不改食材列本身的外觀與行為。
- 不改資料層、通知、Widget、設定頁、食材表單。
- 不改浪費統計與環形圖的內容計算。
- 不處理「浪費率是否該改成正面框架」——獨立的產品題目。
- 不引進新的第三方相依。
- 不沿用 `experiment/home-card-stack` 分支的程式碼。

## Decisions

### 五張卡一疊，選中者排在最後完整顯示

首頁主體是一個垂直堆疊，成員為五張卡：Current、Waste Stats、過期、3 天內到期、保存期限內。未選中者以固定的收合高度排列並被下一張壓住，只露出頂緣；選中者排在整疊的最後，因此不被任何卡遮擋而完整顯示。

「選中者排最後」是刻意的：那是 Wallet 的順序，前景卡在視覺最下方。替代做法是維持固定的緊急度順序、讓選中者原地展開，但那樣最後一張在未選中時會露出整片空白（沒有下一張壓住它），必須另外裁切，反而更繞。

代價是卡片的顏色順序會隨選取變動。五張卡之後它讀起來像一疊牌而非紅綠燈號誌，接受。

### 點一下移到前面，再點一次才開清單

點任何卡片只把它移到最前面。已經在最前面的分桶卡再點一次，才開啟該桶的清單。摘要卡不開啟任何東西。

否決「點分桶卡即自動開啟」：那會讓使用者無法單純瀏覽這疊卡——任何一次點擊都被丟進 modal，而這疊卡的價值正是「一眼看完五張再決定動哪個」。

因為開啟不是第一次點擊的結果，前景的分桶卡必須帶一個可見的指示符號提示「再點可開啟」。該提示只在「已在最前面、且該桶有內容」時出現，避免對摘要卡與空桶誤導。

### 分桶清單是獨立的 MVVMC feature，以 UIKit 導覽控制器呈現於 sheet

新增 `BucketList` feature（View／ViewModel／HostController），由首頁 HostController 經 `AppRouter` 的既有 sheet 方法呈現，呈現時包在一層 `UINavigationController` 內。

這是本設計的關鍵決策，理由有三。

其一，**四個手勢免費回來**。sheet 內是完整的 `List`，滑動、長按、點擊全部由系統提供，首頁一個自訂手勢都不必寫。

其二，**編輯表單推在 sheet 內**。`AppRouter` 一律從 source view controller 動態取得導覽控制器，所以 `BucketListHostController` 發起的推入會落在 sheet 自己的堆疊上，關閉表單後退回清單而非首頁。這正是 `navigation` 既有的機制，不需要修改 `AppRouter`。

其三，**維持 MVVMC 的分層**。清單有自己的 ViewModel 與 State，導航意圖由 ViewModel 發出、HostController 執行，與專案其餘 feature 一致。

替代做法是用 SwiftUI 的 sheet 直接呈現一個 View：少寫三個檔案，但編輯表單無處可推（只能關掉 sheet 再推到首頁堆疊上，關閉後回到首頁而非清單），且繞過 `AppRouter`，與 `navigation` 的集中式導航要求衝突。否決。

### 卡面內容是金額與時間兩個事實，沒有金額時時間升為主要資訊

分桶卡的內容區顯示兩件不同的事：金額（這一桶損失或即將損失多少）與時間（該桶最近一筆多久到期）。有金額時金額為主、時間為輔；沒有已記錄價格時，時間升為主要資訊。

不使用固定文案（例如「已經過期了」「還救得回來」）：那些字串是每桶固定的，與卡片標題在講同一件事，不帶新資訊。

時間一律取該桶的第一筆。清單依到期日升冪排序（見 `persistence` 的查詢排序契約），所以未過期的桶取到的是「最快到期」，已過期的桶取到的是「過期最久」。不需要新的計算。

**不補零、不提示去記錄價格**：`home-ui` 已有 requirement 明文禁止，理由是零金額是假話——真相是使用者沒填價格，而價格是選填欄位。時間之所以是正確的替代，是因為到期日為必填，永遠算得出來。

### 分桶卡的內容區高度固定

三張分桶卡的內容區採同一個固定高度，不論該桶有無金額。否則切換分桶時整疊高度會變，卡片位置跳動。

摘要卡不套用該高度：環形圖與浪費統計的內容本來就比較高，強行對齊會產生大片空白。整疊的最大高度因此由摘要卡決定。

### 摘要卡的內容置於淺色面板內，分桶卡的內容直接畫在卡面上

環形圖與浪費統計是深色前景的內容，畫在飽和色卡面上會失去可讀性，因此包在一層淺色面板中。分桶卡的內容只有數字與短句，以白色直接寫在卡面上即可，不需要再包一層。

`StatusChartView` 內部自帶分隔，放進面板後會呈現為兩塊各自獨立的區塊。該元件由 Widget 共用，調整時必須確認 Widget 的呈現未受影響。

### 首頁不再使用 List，改為捲動容器

五張卡是一個自訂堆疊（卡片之間需要負間距互相疊壓），`List` 的 section 無法表達這種重疊。首頁因此改為捲動容器加垂直堆疊。

首頁不再有食材列，所以**放棄 `List` 不會損失任何手勢**——需要手勢的列全部在 sheet 內，而那裡仍是 `List`。這是前一個決策成立後才出現的選項；若清單留在首頁，離開 `List` 的代價會是重寫四個手勢。

## Implementation Contract

**行為（使用者可觀察）**

1. 首頁顯示五張卡：Current、Waste Stats、過期、3 天內到期、保存期限內。未選中者只露出頂緣（標題、數量或比率），選中者完整顯示其內容。
2. 點任一卡片，該卡移到最前面完整顯示，其餘退為露頂。此時不開啟任何 modal。
3. 已在最前面且有內容的分桶卡，卡面帶一個指示符號；再點一次開啟該桶的清單。摘要卡與空的分桶卡沒有該符號，再點也不開啟。
4. 分桶清單以 sheet 呈現，標題為該桶名稱，並提供關閉方式。清單中的每一列行為與改動前完全相同：點擊編輯、左滑標記已使用、右滑刪除、長按提供延長／標記已使用／標記丟棄。
5. 在清單中點食材開啟編輯表單時，表單出現在 sheet 內；關閉表單後回到清單，而非回到首頁。
6. 在清單中處置食材後，清單即時反映；關閉 sheet 後首頁的卡片數字與金額同步更新。
7. 分桶卡的內容：有已記錄價格時顯示金額為主、最近一筆到期時間為輔；沒有已記錄價格時只顯示到期時間。空桶顯示無項目。任何情況都不顯示零金額，也不出現鼓勵記錄價格的提示。
8. 切換不同分桶卡時，整疊高度不變。
9. 資料變動後（含由助理、通知、Spotlight 觸發者）首頁卡片與開啟中的清單都反映最新結果。

**介面／資料形狀**

- 首頁 State 新增：目前選中的卡片身分。`Sendable`，State 維持 `Equatable`。
- **呈現清單是導航，不是狀態**：`navigation` 要求導航意圖由 ViewModel 發出、HostController 執行，而 sheet 由 `AppRouter` 呈現。因此「要看哪一桶的清單」走 Router，首頁 State **不**持有待呈現的分桶。首頁也因此不需要「清單已關閉」的回報——清單內的寫入會經由資料層的變動廣播讓首頁即時更新（見 `persistence` 的單一出口廣播）。
- 新增一個表示「首頁卡片身分」的列舉，成員為五張卡；分桶卡可取得其對應的 `ExpiryStatus`，摘要卡為 nil。
- 首頁 ViewAction 新增「點擊卡片」一個 case。
- 首頁 Router 新增「呈現分桶清單」的意圖，由首頁 HostController 以 `AppRouter` 的 sheet 方法執行，內容包在 `UINavigationController` 內。
- 新增 `BucketList` feature：View、ViewModel、State、HostController 各一。其 ViewModel 的 Router 至少含「編輯某食材」與「關閉」兩種意圖。
- `AppRouter` 的既有方法簽章與行為不變。
- `project.yml` 不需新增 target；新檔案落在既有的 `Sources/Features` 來源路徑下。

**失敗模式**

- 分桶為空時不呈現 sheet，卡片仍可被選中。
- 選中的分桶因資料變動而變空時，選取自動移到最急迫的非空分桶（沿用現行行為）。
- 讀取失敗維持現況：回空集合、不報錯（見 `persistence`）。
- 寫入失敗維持現況：清單所在畫面不自行報錯（見 `persistence` 的判準——失敗後畫面維持不變者可忽略）。

**驗收標準**

- 新增首頁 ViewModel 測試：點擊未選中的卡片只改變選中身分且不設定待呈現分桶；點擊已選中且非空的分桶卡才設定待呈現分桶；點擊已選中的摘要卡不設定；點擊已選中但為空的分桶卡不設定；收到「清單已關閉」後待呈現分桶回到 nil。
- 新增 `BucketList` ViewModel 測試：點列發出編輯意圖、關閉發出關閉意圖、處置動作後清單內容更新。
- 既有 `HomeViewModelTests` 全數維持通過。
- 完整測試套件通過且測試數不減少。
- 模擬器實機驗證並記錄：分桶卡在前景與摘要卡在前景兩種狀態的整疊高度；三張分桶卡在前景時的高度彼此相同。
- 模擬器實機驗證：從清單點食材開啟編輯表單後，關閉表單回到清單而非首頁。
- String Catalog：stale 數 = 0、缺翻譯數 = 0。
- Widget 的呈現未因 `StatusChartView` 的調整而改變（以模擬器截圖比對）。

**範圍邊界**

- 範圍內：首頁的 View／ViewModel／State／HostController、新增的 `BucketList` feature、`StatusChartView` 在卡片內的呈現調整、底部按鈕間距註解、String Catalog，以及 `home-ui`／`navigation`／`app-intents` 三份 spec 的 delta。
- 範圍外：食材列元件本身、食材表單、設定頁、資料層、通知服務、Widget 的版面、`Deeplink`。
- **範圍內的例外：`AppRouter` 的返回行為**。實作時發現既有的返回邏輯在「被 push 到呈現式堆疊上的畫面」會收掉整個堆疊而非退回前一頁——那段判斷是為「整個堆疊被呈現、而來源是它的根畫面」寫的，對疊在根上面的畫面不成立。本 change 的 Implementation Contract 第 5 點與 `navigation` 新增的 scenario 都直接依賴這個行為，因此必須在此修正，不能留給後續。

## Risks / Trade-offs

- **[食材清單不再能一眼看完三桶]** → 刻意的取捨。三個桶的數量與金額仍在卡面上一覽無遺，只有「列的內容」需要多一次點擊。實際使用時使用者一次只處理一個桶。
- **[卡片顏色順序隨選取變動]** → 五張卡之後整體讀起來是一疊牌而非號誌，接受。若日後認定順序語意重要，替代方案（固定順序、原地展開）已記錄在決策中。
- **[`AppRouter.back` 的修正影響所有返回路徑]** → 新增的判斷只在「來源以 push 抵達且堆疊深度大於一」時改變行為；該情形下舊邏輯若走到 dismiss 分支即為錯誤，若走到 default 分支本來就是 pop，結果相同。既有的「呈現式堆疊根畫面返回即收起」行為以單元測試釘住。
- **[多一層 modal]** → 編輯表單變成「sheet 內的推入」，比原本多一層。但關閉行為更符合預期（退回清單而非跳回首頁），且 `AppRouter` 既有的返回機制可直接處理。
- **[`StatusChartView` 由 Widget 共用]** → 調整其在卡片內的呈現時可能影響 Widget。驗收標準要求以截圖比對 Widget 未變。
- **[首頁離開 `List`]** → 失去 `List` 的列相關能力（滑動、分隔線、未來的多選／排序）。但首頁不再有列，需要那些能力的畫面在 sheet 內仍是 `List`。若日後首頁又要放列，這個決策需要重新檢視。
- **[螢幕感知標註移位]** → 助理解析「這個」的對象從首頁移到分桶清單。`app-intents` 明文指出該能力是否真的生效不在本專案控制範圍內、不作為驗收條件，因此影響有限，但 spec 敘述必須更新以免誤導。
