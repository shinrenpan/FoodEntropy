## Context

食材列目前顯示縮圖、名稱、到期描述與一個效期色點，沒有價格。價格是 `add-price-tracking` 加入的選填欄位，只出現在編輯表單與兩處彙總（分桶卡的該桶總額、浪費統計的已丟棄總額）。

首頁的分桶卡在前景時會顯示該桶的金額總和。點進清單後完全看不到金額，兩個畫面之間因此有一道斷層。

食材列元件目前**只有分桶清單在渲染**。它所在的檔案同時定義了效期顏色函式，widget target 因此編譯了該檔案，但 widget 並未使用該元件——這點先前被誤判為「動它要重驗 widget」，實際不必。

選取分桶的缺陷出在資料載入的收尾：選中的分桶若為空就改選最急迫的非空桶。該判斷無法區分「剛剛變空」與「原本就空、使用者刻意選的」，而載入在畫面出現、回到前景、資料層廣播三個時機都會發生。`home-ui` 有一條 scenario 明說點空的分桶卡會讓它移到前面，兩者矛盾。

## Goals / Non-Goals

**Goals:**

- 在分桶清單的列上看得到該筆的已記錄價格。
- 沒有記錄價格的列不出現任何金額相關的視覺元素。
- 使用者一旦自己選過卡片，重載不再更動他的選擇。
- 首次開啟仍落在最急迫的非空分桶。

**Non-Goals:**

- 不改價格的輸入、計算或儲存。
- 不改分桶卡上的金額（該桶總和，與列上的單筆是不同數字）。
- 不改 widget。
- 不為缺價格的列補佔位符號。
- 不改空分桶卡「點兩次也不開清單」的行為。

## Decisions

### 價格為列的尾端次要資訊，缺值時整個不渲染

價格顯示在列的尾端、效期色點之前，字級低於名稱與到期描述——它是輔助判斷的資訊，不是這一列的主角（主角是「這是什麼、多久壞」）。

沒有記錄價格時不顯示任何東西，不補零也不補符號。這與 `home-ui` 既有的「金額為零時整行消失」同一個理由：零是假話，真相是使用者沒填。

**不補對齊用的破折號**，這一點與卡片堆疊的做法刻意不同：五張卡是同一欄對齊的數值，缺一格看起來像漏渲染；清單的列各自獨立成行，尾端有無數值在 iOS 清單是常態，補符號只是增加噪音。

### 自動挑選分桶只決定初始那一張

新增一個狀態欄位記錄「使用者是否已經自己選過卡片」，於點擊卡片時設為真。載入收尾的自動挑選只在該欄位為偽時生效。

如此首次開啟仍會落在最急迫的非空分桶（那時沒有使用者選擇可尊重），而之後不論重載幾次、選的是不是空桶，都不會推翻他的決定。

替代方案是「完全移除自動挑選」：首次開啟會停在預設的過期卡，即使它是空的而其他桶有內容。否決——那讓初始狀態變差，而初始狀態本來就沒有選擇需要被尊重。

另一個替代是「記住選擇但空桶時仍換走」：那正是目前的行為，也正是缺陷本身。

## Implementation Contract

**行為（使用者可觀察）**

1. 分桶清單中，有記錄價格的食材列在尾端顯示該筆金額，格式依裝置地區。
2. 沒有記錄價格的食材列不顯示金額，也不顯示任何代替金額的符號或提示。
3. 列的四個動作（點擊編輯、左滑標記已使用、右滑刪除、長按選單）與加入價格前完全相同。
4. 首次開啟 app 時，完整顯示的是最急迫的非空分桶卡；三桶皆空時是過期卡。
5. 使用者點過任一張卡之後，離開首頁再返回、app 回到前景、或資料變動觸發重載，完整顯示的仍是他選的那一張——即使那一桶沒有內容。
6. 選中的分桶在使用者停留期間變空（例如在清單中處置了最後一筆），仍維持選中該桶，卡片顯示無項目。

**介面／資料形狀**

- 食材列元件新增一個顯示價格的區塊，資料取自既有的 Domain Model 欄位，不新增參數以外的相依。
- 首頁 State 新增一個布林欄位記錄使用者是否已自行選過卡片，預設偽，`Sendable`，State 維持 `Equatable`。
- 首頁 ViewAction、Router 與既有欄位不變。
- 金額格式化沿用既有的貨幣格式化入口，不自行組字串。

**失敗模式**

- 價格為 nil 時不渲染任何金額元素（非顯示零、非顯示佔位符）。
- 取不到貨幣資訊的 locale 沿用既有格式化入口的既有行為（退為純數字，不硬編幣別）。

**驗收標準**

- 新增首頁 ViewModel 測試：使用者未選過卡時，載入會把選取移到最急迫的非空桶；使用者選過卡之後，再次載入不更動其選取，即使該桶為空。
- 新增測試涵蓋「選中的桶在停留期間變空仍維持選中」。
- 既有 `HomeViewModelTests` 與 `BucketListViewModelTests` 全數維持通過。
- 完整測試套件通過且測試數不減少。
- 模擬器實機驗證：分桶清單中，有價格與無價格的列並存時，前者顯示金額、後者尾端沒有任何金額相關元素。
- 模擬器實機驗證：選中一張卡後進入設定頁再返回，完整顯示的仍是同一張卡。
- String Catalog：stale 數 = 0、缺翻譯數 = 0。

**範圍邊界**

- 範圍內：食材列元件的價格呈現、首頁 State 與載入收尾的選取邏輯、對應單元測試，以及 `home-ui` 的 delta。
- 範圍外：價格的輸入與儲存、分桶卡的金額、widget、通知、資料層、`BucketList` 的其餘行為。

## Risks / Trade-offs

- **[列的資訊密度增加]** → 價格是尾端次要資訊、字級較低，且多數列可能沒有價格（選填欄位）。若實機觀察後覺得擁擠，調整的是字級與間距，不是把資訊搬走。
- **[缺價格的列尾端參差]** → 刻意接受。iOS 清單的列本來就容許尾端有無 detail 文字，與卡片堆疊那種同欄對齊的情境不同。
- **[新增的狀態欄位讓 State 多一個旗標]** → 它記錄的是使用者意圖而非畫面資料，屬於必要狀態；替代做法（完全移除自動挑選）會讓初始狀態變差。
